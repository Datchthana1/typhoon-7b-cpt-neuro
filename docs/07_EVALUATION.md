# 07 — การประเมินผล: Perplexity คืออะไร และอ่านอย่างไร

## Perplexity คืออะไร

**Perplexity (PPL) = "โดยเฉลี่ยแล้ว โมเดลลังเลระหว่างกี่ตัวเลือก ตอนเดาคำถัดไป"**

นิยามทางคณิตศาสตร์:

```
PPL = exp( ค่าเฉลี่ยของ cross-entropy loss ต่อ token )
```

หรือกลับกัน: `loss = ln(PPL)` — สองค่านี้คือตัวเดียวกันคนละหน่วย

### ตีความด้วยตัวอย่าง

สมมติโมเดลกำลังอ่านประโยค `"สมองของมนุษย์มีเซลล์ประสาทประมาณ ___"`

| PPL | ความหมาย | เทียบเท่ากับ |
|---|---|---|
| **1.0** | รู้คำถัดไปแน่นอน 100% | ทายถูกทุกครั้ง (เป็นไปไม่ได้จริง) |
| **10** | ลังเลระหว่าง ~10 คำ | เหมือนเดาเลข 1 หลัก |
| **100** | ลังเลระหว่าง ~100 คำ | เริ่มมั่วแล้ว |
| **35,219** | ไม่รู้อะไรเลย | เดาสุ่มจาก vocab ทั้งหมดของ typhoon-7b |

> **ยิ่งต่ำยิ่งดี** — PPL ต่ำ = โมเดล "คุ้นเคย" กับข้อความแบบนั้น
> PPL สูง = ข้อความนั้นอยู่นอกสิ่งที่โมเดลเคยเห็น

---

## ทำไมเลขน้อยถึงดีกว่า — อธิบายจากต้นทาง

### ขั้นที่ 1 — โมเดลไม่ได้ "ตอบคำ" แต่ "แจกความน่าจะเป็น"

ทุกครั้งที่โมเดลจะทำนาย token ถัดไป มันไม่ได้เลือกคำเดียว
แต่ให้คะแนนความน่าจะเป็นกับ **ทุกคำใน vocabulary พร้อมกัน** (typhoon-7b มี 35,219 คำ)

```
"สมองของมนุษย์มีเซลล์ประสาทประมาณ ___"

   แปด      → 0.31
   หนึ่ง     → 0.24
   หลาย     → 0.11
   ร้อย     → 0.05
   ...       (อีก 35,215 คำ รวมกันได้ 0.29)
   ────────────────────
   รวม               1.00
```

### ขั้นที่ 2 — Loss คือ "โมเดลให้ความน่าจะเป็นกับคำที่ถูก*เท่าไร*"

ถ้าคำที่ตามมาจริง ๆ คือ `แปด` โมเดลให้ไว้ 0.31

```
loss ของ token นี้ = −ln(0.31) = 1.171
```

- ให้ความน่าจะเป็นสูง (มั่นใจถูก) → `−ln` ออกมา**น้อย** → loss ต่ำ
- ให้ความน่าจะเป็นต่ำ (เดาผิด) → `−ln` ออกมา**มาก** → loss สูง

เครื่องหมายลบอยู่ตรงนั้นเพราะ `ln` ของเลขที่น้อยกว่า 1 เป็นค่าลบเสมอ

### ขั้นที่ 3 — PPL คือส่วนกลับของความน่าจะเป็นนั้น

```
PPL = exp(ค่าเฉลี่ยของ loss) = 1 ÷ (ค่าเฉลี่ยเรขาคณิตของความน่าจะเป็น)
```

**นี่คือสมการที่ทำให้ทุกอย่างเข้าใจง่ายขึ้นทันที:**

| โมเดลให้ความน่าจะเป็นกับคำที่ถูก | loss | **PPL** |
|---|---|---|
| 100% (1.00) | 0.000 | **1.0** |
| 50% (0.50) | 0.693 | **2.0** |
| 10% (0.10) | 2.303 | **10.0** |
| 1% (0.01) | 4.605 | **100.0** |
| 1/35,219 (เดาสุ่ม) | 10.469 | **35,219** |

> **PPL = 1 ÷ ความน่าจะเป็นเฉลี่ยที่โมเดลให้กับคำที่ถูกต้อง**

เลขน้อยจึงดีกว่าเพราะมันคือ**ส่วนกลับ** — PPL ต่ำแปลว่าตัวหารใหญ่
คือโมเดลมั่นใจในคำที่ถูกต้องมากขึ้น

### แปลตัวเลขจริงของโปรเจกต์นี้กลับเป็นเปอร์เซ็นต์

| | PPL | โมเดลให้ความน่าจะเป็นกับคำที่ถูก |
|---|---|---|
| ก่อน CPT | 11.073 | 1 ÷ 11.073 = **9.03%** |
| หลัง CPT | 10.051 | 1 ÷ 10.051 = **9.95%** |
| การรันที่ล้มเหลว | 45.127 | 1 ÷ 45.127 = **2.22%** |

อ่านได้ว่า: เดิมโมเดลมั่นใจในคำถัดไปเฉลี่ย 9.03% หลังเทรนเพิ่มเป็น 9.95%
ส่วนการรันที่พังทำให้ความมั่นใจร่วงเหลือ 2.22% — คือมั่วหนักกว่าเดิมสี่เท่า

### ทำไมต้อง `exp()` ไม่ใช่เฉลี่ยธรรมดา

ความน่าจะเป็นของ*ทั้งประโยค*คือ**ผลคูณ**ของความน่าจะเป็นทุก token

```
P(ประโยค) = P(คำ1) × P(คำ2) × ... × P(คำn)
```

ค่าเฉลี่ยที่ถูกต้องสำหรับสิ่งที่คูณกันคือ **ค่าเฉลี่ยเรขาคณิต** ไม่ใช่ค่าเฉลี่ยเลขคณิต
การทำ `exp(เฉลี่ยของ −ln p)` คือวิธีคำนวณค่าเฉลี่ยเรขาคณิตพอดี
นี่คือเหตุผลทางคณิตศาสตร์ที่ PPL นิยามด้วย `exp` ไม่ใช่นิยามแบบอื่น

## "การเทียบ PPL" หมายถึงอะไร

PPL **ไม่มีความหมายในตัวเอง** — ตัวเลข 10.05 ลอย ๆ ไม่บอกอะไรเลย
มันมีความหมายก็ต่อเมื่อ**เทียบกับอีกค่าหนึ่ง**ที่วัดภายใต้เงื่อนไขเดียวกันทุกอย่าง

### เงื่อนไข 4 ข้อที่ต้องเหมือนกันเป๊ะ ไม่งั้นเทียบไม่ได้

| # | ต้องเหมือนกัน | ถ้าต่างกันจะเกิดอะไร |
|---|---|---|
| 1 | **ชุดข้อความที่ทดสอบ** | ข้อความง่าย (ข่าวสั้น) ได้ PPL ต่ำกว่าข้อความยาก (กฎหมาย) เสมอ — เทียบข้าม dataset คือเทียบคนละอย่าง |
| 2 | **Tokenizer** | PPL คิดต่อ token — tokenizer ที่หั่นภาษาไทยละเอียดกว่าจะได้ PPL ต่ำกว่าโดยอัตโนมัติ ทั้งที่โมเดลไม่ได้เก่งขึ้น **จึงห้ามเทียบ PPL ของ typhoon-7b กับ Llama หรือ Qwen เด็ดขาด** |
| 3 | **ความยาว context** | context ยาวกว่า = มีข้อมูลมากกว่า = PPL ต่ำกว่า (โปรเจกต์นี้ล็อกไว้ที่ `seq_len=1024` ทุกครั้ง) |
| 4 | **วิธีคำนวณ** | นับ token ที่มี label จริงหรือรวม padding ด้วย · เฉลี่ยต่อ batch หรือถ่วงน้ำหนักด้วยจำนวน token — ให้ผลต่างกันได้หลายเปอร์เซ็นต์ |

ในโปรเจกต์นี้ทั้ง 4 ข้อถูกล็อกไว้เหมือนกันหมด **ต่างกันแค่น้ำหนักโมเดล** (base vs base+adapter)
→ การเทียบจึงถูกต้อง และความต่างที่เห็นมาจากการเทรนล้วน ๆ

### สิ่งที่เราเทียบจริง ๆ มี 2 คู่

```
คู่ที่ 1  โมเดลตั้งต้น  vs  โมเดลหลังเทรน   บน val ของโดเมนใหม่
          11.073            10.051           → เรียนรู้ได้ไหม  (อยากให้ลด)

คู่ที่ 2  โมเดลตั้งต้น  vs  โมเดลหลังเทรน   บน Wikipedia ไทย
           8.034             7.725           → ลืมของเดิมไหม  (อยากให้นิ่ง)
```

**คู่ที่ 2 คือหัวใจที่คนมักลืม** เพราะถ้าดูแค่คู่ที่ 1 คุณจะเลือก hyperparameter
ที่กดคู่ที่ 1 ลงได้เยอะที่สุด ซึ่งมักเป็นค่าเดียวกับที่ทำให้คู่ที่ 2 พุ่ง = โมเดลพัง

### คิดเปอร์เซ็นต์อย่างไร

เป็น**การเปลี่ยนแปลงเชิงสัมพัทธ์** ไม่ใช่ผลต่างดิบ

```
(10.051 − 11.073) ÷ 11.073 × 100 = −9.2%
```

ใช้เปอร์เซ็นต์เพราะ PPL เป็นสเกลเชิงคูณ การลดจาก 100 → 90 กับ 10 → 9
คือ "ดีขึ้นเท่ากัน" ในเชิงความหมาย แม้ผลต่างดิบจะต่างกันสิบเท่า

### ทำไม Optuna ใช้ `loss` ไม่ใช่ `PPL`

objective ของ HPO คือ

```
score = domain_loss + λ · max(0, general_loss − general_loss_baseline)
```

ถ้าใช้ PPL ตรง ๆ พจน์ที่มีค่ามาก (เช่น 45) จะครอบงำพจน์ที่มีค่าน้อย (เช่น 8) จนพจน์หลังแทบไม่มีผล
แต่ `loss = ln(PPL)` บีบทุกอย่างลงมาอยู่ในสเกลใกล้กัน (ln 45 = 3.8 · ln 8 = 2.1)
การบวกกันใน log-space จึงยุติธรรมกับทั้งสองพจน์

## อ่านผลของโปรเจกต์นี้

```
PPL โดเมนใหม่      11.073 → 10.051   (−9.2%)
PPL ไทยทั่วไป        8.034 →  7.725   (−3.8%)
```

### แถวที่ 1 — PPL โดเมนใหม่ (บทความ neuroplasticity)

**ก่อนเทรน 11.073** = อ่านบทความเรื่องสมองแล้วลังเลเฉลี่ยระหว่าง ~11 คำต่อหนึ่งตำแหน่ง
**หลังเทรน 10.051** = ลังเลลดเหลือ ~10 คำ

→ **ลดลง = ดีขึ้น** โมเดลคุ้นเคยกับสำนวนและคำศัพท์แนวนี้มากขึ้น

### แถวที่ 2 — PPL ภาษาไทยทั่วไป (Wikipedia)

นี่คือ **ตัวจับ catastrophic forgetting** ไม่ใช่ตัววัดความสำเร็จ

**ค่าที่ต้องการคือ "ไม่เปลี่ยนมาก"** ไม่ใช่ "ยิ่งต่ำยิ่งดี"

| ผลที่ได้ | หมายความว่า |
|---|---|
| เพิ่มขึ้น > 5% | 🔴 โมเดลกำลังลืมภาษาไทยทั่วไป — เสียหาย |
| เปลี่ยนแปลง ±5% | 🟢 ปลอดภัย |
| **ลดลง (−3.8% ในกรณีนี้)** | 🟢 ไม่ลืม และบังเอิญดีขึ้นด้วย (เพราะ replay corpus เป็น Wikipedia ไทย) |

## ทำไม −9.2% จึงยังไม่พอ

ตัวเลขดูดี แต่ต้องอ่านคู่กับสามข้อนี้

### 1. Validation set มีเพียง **1 บล็อก**

PPL คำนวณจากข้อความ 1,024 token เท่านั้น ความผันผวนตามธรรมชาติของ PPL
บนตัวอย่างขนาดนี้อยู่ที่ราว ±10% อยู่แล้ว → **−9.2% แยกจาก noise ไม่ได้**

ต้องมี val อย่างน้อย **30–50 บล็อก** ตัวเลขจึงมีความหมายทางสถิติ

### 2. PPL วัด "ความคุ้นเคย" ไม่ได้วัด "ความถูกต้อง"

โมเดลอาจคุ้นกับ*รูปแบบประโยค*แบบสารคดีวิทยาศาสตร์ โดยที่*เนื้อหา*ยังผิดหมด
เพราะ PPL ให้คะแนนตามความน่าจะเป็นของ token ไม่ได้ตรวจว่าข้อเท็จจริงถูกไหม

ประโยค "ไมอีลินเสียหายทำให้เป็นโรคพาร์กินสัน" (ผิด)
มี PPL ต่ำพอ ๆ กับ "ไมอีลินเสียหายทำให้การนำสัญญาณช้าลง" (ถูก)
เพราะทั้งคู่เป็นภาษาไทยที่ลื่นไหลเหมือนกัน

### 3. Generation probe เผยความจริงที่ PPL ซ่อนไว้

เมื่อรัน `python main.py probe` โมเดลตอบว่า:

> "ทฤษฎีพฤติกรรมสร้างนิสัยของแม็กซ์เวลล์ (**Maslow's Habit Formation Theory**)
> ซึ่งอ้างอิงจากงานวิจัยในปี **ค.ศ. 1937**"

ทฤษฎีนี้**ไม่มีอยู่จริง** และสับสน Maxwell Maltz (1960) กับ Maslow
→ PPL ดีขึ้นแต่โมเดลยังหลอน
