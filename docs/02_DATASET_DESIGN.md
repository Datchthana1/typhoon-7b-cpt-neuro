# 02 — การออกแบบ Dataset สำหรับ CPT

## หลักการเดียวที่ทุกอย่างตามมา

> **CPT ฝัง *การกระจายทางสถิติของข้อความ* เข้าไปในน้ำหนักโมเดล**

ไม่ใช่แค่ "ความรู้" — แต่รวมถึงรูปแบบทุกอย่างที่ปรากฏบ่อยในคลังข้อมูล
ความยาวประโยค ตำแหน่งที่ขึ้นบรรทัดใหม่ ความถี่ของ bullet สำนวนขึ้นต้นย่อหน้า

ทุกรูปแบบที่ปรากฏบ่อยจะกลายเป็น**แนวโน้มที่โมเดลผลิตออกมา**ภายหลัง
และเมื่อฝังไปแล้ว การแก้ด้วย prompt แทบไม่ได้ผล

---

## ทำไมต้อง "ประโยคยาว" โดยเฉพาะ

โจทย์ของโปรเจกต์นี้ระบุว่าต้องการให้โมเดลเขียนประโยคยาว ๆ ไม่ใช่ Q&A
ในเชิงเทคนิคนี่แปลว่าอะไร

| ถ้าคลังข้อมูลเป็น... | โมเดลจะเรียนว่า... | ผลที่ได้ตอน generate |
|---|---|---|
| bullet list | หลัง 5–15 token ต้องขึ้นบรรทัดใหม่ | ประโยคห้วน แตกเป็นข้อ |
| Q&A | หลัง `?` ต้องตามด้วยคำตอบ | กลายเป็น pseudo-instruct ที่แย่กว่า SFT จริง |
| ย่อหน้ายาว | ต้องรักษาความต่อเนื่องข้ามหลายร้อย token | เขียนความเรียงต่อเนื่องได้ |

การเทรนบนย่อหน้ายาวจึงเป็นการฝึกความสามารถ **long-range coherence** โดยตรง
เพราะโมเดลต้องเรียนที่จะคาดการณ์ token ที่ 500 โดยอ้างอิงบริบทตั้งแต่ token ที่ 1

**เป้าหมายเชิงตัวเลข** (บังคับใช้ใน [book/STYLE_GUIDE.md](../book/STYLE_GUIDE.md)):
- ประโยค **35–60 คำ**
- ย่อหน้า **180–320 คำ** (4–7 ประโยค)
- บทหนึ่งยาวกว่า `seq_len` มาก เพื่อให้แต่ละบล็อกมาจากบริบทเดียวกัน

## เหตุผลที่ห้ามรูปแบบเหล่านี้เด็ดขาด

| ห้าม | เหตุผลเชิงกลไก |
|---|---|
| Q&A | สร้าง instruction-following pattern ที่อ่อนแอ ซึ่งจะขัดกับ SFT ที่ทำทีหลัง |
| bullet / เลขข้อ | สอนให้ขึ้นบรรทัดใหม่ถี่ ทำลายความสามารถเขียนย่อหน้ายาว |
| markdown (`**`, `##`, `` ` ``) | กลายเป็น token ที่พ่นออกมาโดยไม่มีเหตุผล |
| meta-text ("ในบทนี้เราจะ...") | เป็นสำนวนผู้ช่วย AI ไม่ใช่สำนวนหนังสือ ดึงกลับยากมาก |
| การอ้างอิงแบบ APA `(Author, 2004)` | โมเดลจะพ่นวงเล็บ+ปีสุ่ม ๆ ในทุกบริบท — แย่กว่าไม่อ้างเลย |

การอ้างอิงต้องเขียน**กลืนไปในประโยค** เช่น
> "งานของดรากันสกีและคณะที่ตีพิมพ์ในวารสาร Nature เมื่อปี 2004 พบว่า..."

## ทำไมต้องมี FACT_TABLE ก่อนเขียน ไม่ใช่ตรวจทีหลัง

หัวข้อ "สมอง + นิสัย" มีความหนาแน่นของ **ข้อเท็จจริงยอดนิยมที่ผิด** สูงผิดปกติ
(21 วัน · โดพามีน = สารความสุข · ใช้สมอง 10% · หมื่นชั่วโมง · สมองซีกซ้าย-ขวา)

ถ้าปล่อยให้ข้อมูลผิดเข้าไปในคลัง มันจะถูกฝังเข้าน้ำหนักโมเดล
และการดึงออกยากกว่าการป้องกันตั้งแต่ต้นหลายเท่า — ไม่มี "undo" ใน CPT

[book/FACT_TABLE.md](../book/FACT_TABLE.md) จึงมีสถานะเป็น **ground truth** ไม่ใช่เอกสารอ้างอิง
มี 48 รายการแบ่งตามสถานะ ✅ มีหลักฐานหนักแน่น · ⚠️ ถูกขยายเกินจริง · 🔬 ยังถกเถียง · ❌ ถูกหักล้าง

รายการที่ทำเครื่องหมาย 🔬 (เช่น เซลล์ประสาทเกิดใหม่ในผู้ใหญ่) **ต้องเขียนว่ายังไม่ยุติ**
เพราะการฟันธงในประเด็นที่วงการยังเถียงกันคือการสอนความมั่นใจที่ไม่มีมูลให้โมเดล

## ขนาดคลังข้อมูล — ความจริงที่ต้องรับ

| ระดับ | Token | เหมาะกับ |
|---|---|---|
| 10K – 100K | เล็กมาก | ปรับสำนวนเล็กน้อย · **ผลที่วัดจริงได้อยู่ในระดับ noise** |
| 100K – 1M | เล็ก | ปรับสำนวน + คำศัพท์เฉพาะทาง |
| 1M – 10M | กลาง | เริ่มฝังความรู้เชิงโดเมนได้ |
| 10M – 100M | ใหญ่ | CPT ที่เห็นผลชัดในงานวิจัย |
| > 100M | ใหญ่มาก | โดเมนเปลี่ยนได้จริง |

**หนังสือ 500 หน้า ≈ 390–430K token** → อยู่ในระดับ "เล็ก"
ผลที่คาดหวังได้จริงคือ **สำนวนการเขียนและคำศัพท์เฉพาะทาง** มากกว่าการฝังความรู้ทั้งก้อน

*(ในการทดสอบจริงที่รันไป คลังมี 8 บท = 16K token = ระดับ "เล็กมาก" — ดู [RESULTS.md](../RESULTS.md))*

## การเพิ่มปริมาณข้อมูล

เรียงตามคุณภาพจากดีที่สุดไปแย่ที่สุด

### 1. เขียนบทเพิ่ม *(ดีที่สุด)*
ข้อมูลใหม่จริง ไม่มีข้อเสีย เพียงแต่ใช้เวลามาก โครงพร้อมแล้วใน [book/OUTLINE.md](../book/OUTLINE.md)

### 2. Paraphrase augmentation
เขียนบทเดิมใหม่โดยคงข้อเท็จจริง เปลี่ยนสำนวนและโครงสร้างประโยค

- ✅ เพิ่มความหลากหลายของ*วิธีพูดถึง*ข้อเท็จจริงเดียวกัน ซึ่งช่วยให้โมเดล generalize
- ⚠️ ต้องตั้ง `dedup.jaccard_threshold` เป็น **0.90** ไม่งั้น dedup จะตัด augment ทิ้งหมด
- ⚠️ ห้ามเกิน 3 เวอร์ชันต่อบท — มากกว่านั้นเสี่ยงให้โมเดลท่องจำ

### 3. ขยายบทให้ลึกขึ้น
เพิ่มกรณีศึกษา รายละเอียดการทดลอง ประวัติของแนวคิด — ได้ข้อมูลใหม่จริงโดยไม่ต้องเปลี่ยนโครง

### 4. Replay corpus *(คนละวัตถุประสงค์)*
ไม่ได้เพิ่มความรู้โดเมน แต่**ป้องกันการลืม** — ดูหัวข้อถัดไป

## Replay corpus

**ปัญหา:** เมื่อ fine-tune บนการกระจายใหม่ที่แคบ โมเดลจะปรับตัวเข้าหามันจนสูญเสียการกระจายเดิม

**วิธีแก้:** ผสมข้อความจากการกระจายเดิมกลับเข้าไป 10–20% ของ train set

```yaml
data:
  replay_ratio: 0.15   # 0 = ปิด | 0.10-0.20 = แนะนำ | >0.30 = โดเมนใหม่เรียนไม่เข้า
```

โปรเจกต์นี้ใช้ **Thai Wikipedia** (`wikimedia/wikipedia`, config `20231101.th`)
โดยแยกเป็นสองส่วน:

| ไฟล์ | ใช้ทำอะไร | ขนาดที่เตรียมไว้ |
|---|---|---|
| `data/replay/general_th.jsonl` | ผสมเข้า train set | 400 เอกสาร / 2.65M อักขระ |
| `data/replay/general_val.jsonl` | วัด forgetting (**ห้ามผสมเข้า train**) | 40 เอกสาร / 288K อักขระ → 88 บล็อก |

การแยกสองไฟล์นี้สำคัญมาก — ถ้า general_val ปนอยู่ใน train ตัวเลข forgetting จะเป็นเท็จ
